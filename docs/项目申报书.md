# moonmedic 项目申报书

## 1. 项目名称

moonmedic · Kubernetes 滚动发布路径分析与只读取证工具

## 2. 项目简介

Deployment 发布卡住时，moonmedic 读取新旧副本、发布策略和配额，推导当前策略允许哪些替换动作，并附可核对的对象字段。集群访问只读，快照可离线回放。

## 3. 项目方向与通用性说明

**04 开发者工具**。归属判断和路径搜索由 MoonBit 实现，可独立于 kubemoon 和 LLM 运行。其他工具可复用快照接口和 JSON 诊断。

## 4. 预期使用场景

1. **配额已满时的滚动发布**。3 个旧副本可用，另有 1 个 Pod 占位，配额 4/4，新版尚无 Pod。用 `--snapshot` 回放两个无拒绝消息的方案。只把 `maxSurge` 从 1 调到 2，新版期望数可升到 2，但没有名额创建 Pod，也不能先退旧，否则可用副本会少于 3 个。只把 `maxUnavailable` 从 0 调到 1，最低可用数降到 2。回放得到的可行顺序是先退 1 个旧副本，等名额释放后创建新 Pod，待它可用再继续替换。[第三轮技术说明](https://github.com/young9682/moonmedic/blob/a81124b745c86f2b470fc73678593d58c3fa4885/docs/PROPOSAL.md#%E7%AC%AC%E4%B8%89%E8%BD%AE%E5%A4%8D%E6%A0%B8%E4%B8%AD%E7%9A%84%E6%BB%9A%E5%8A%A8%E5%8F%91%E5%B8%83%E5%8F%AF%E8%BE%BE%E6%80%A7)
2. **副本缺失**。期望 2 个副本，用 `--deployment` 核对归属 Pod、RS 的 `FailedCreate` 以及同名同资源的配额。E01 中零 Pod、配额 0/0，缺 2 个名额。E02 已有 1 个 Pending Pod、配额 1/1，只缺 1 个。
3. **两条拒绝都含 `is forbidden`**。查看归属 RS 的拒绝原文。[E03](https://github.com/young9682/moonmedic/blob/db589648b145acbe69b87dea9ab3baeff02ebbd4/eval/fixtures/e03-limitrange-reject.snapshot.json) 中 `maximum memory usage per Container is 64Mi, but limit is 256Mi` 命中 `limitrange_reject`。[R02](https://github.com/young9682/moonmedic/blob/db589648b145acbe69b87dea9ab3baeff02ebbd4/eval/fixtures/r02-generic-validation.snapshot.json) 中 `spec.template: Invalid value: unsupported field value` 只报创建失败和零 Pod。

## 5. 拟实现的核心功能

按模板识别新旧 RS，校验 UID、Pod 数和配额用量。广度优先搜索扩缩容、创建、变为可用和释放名额的顺序。找到路径就列出动作，穷尽后才判定受阻。

模型限两个归属 RS、健康旧副本、整数策略和单一 Pod 数量配额，假设新 Pod 可用、缩容能释放名额。证据不完整或达到搜索上限时停止推断。LimitRange 仍按受支持句式与数值归因，同文案的第三方插件需核对来源。

55 项单测、15 项离线回放通过。Kubernetes v1.33.1 现场保持 unavailable=0，只把配额从 4 提到 5，新版达到 3/3，旧版退到 0。只把 unavailable 改为 1 的另一场试验在 540 秒时为 2/3。[完整恢复](https://github.com/young9682/moonmedic/actions/runs/44674774969) · [部分恢复](https://github.com/young9682/moonmedic/actions/runs/44673527277)
