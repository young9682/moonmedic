# moonmedic 项目申报书

## 1. 项目名称

moonmedic · MoonBit 实现的 Kubernetes 故障证据引擎

## 2. 项目简介

Deployment 发布后未生成预期 Pod 时，值班人员需要在控制器状态、事件和命名空间配额之间交叉取证。moonmedic 从 Deployment 出发，沿 ReplicaSet 与 Pod 的 UID 归属关系取证，分别报告创建失败、缺失副本和可识别的拒绝原因。诊断引用对应对象、字段和观测值。实时取证使用 Kubernetes GET 接口，快照可离线回放，报告可选用 LLM 归纳。

## 3. 项目方向与通用性说明

主方向为 **04 开发者工具**。诊断内核用 MoonBit 实现，快照和规则包独立于 kubemoon 与 LLM。其他 MoonBit 工具可复用快照解码、诊断接口和 JSON 证据结构。评测快照可用于离线回归和工具对照。

## 4. 预期使用场景

1. **Pod 从未创建（E01）**。以 `--deployment` 读取 Deployment，再按 UID 找到其 ReplicaSet。读取 `ReplicaFailure` 条件和 `FailedCreate` 事件，关联同名 ResourceQuota 的 `used/hard` 与拒绝消息的资源项，最后核对归属 Pod 数。实测快照期望 2 副本、配额 `pods=0`，报告还差 2 个配额。
2. **仅部分副本创建（E02）**。期望 2 副本且已有 1 个归属 Pod，报告缺少 1 个配额，并引用副本数与当前配额。
3. **LimitRange 拒绝（E03）**。容器内存上限 256Mi 触发 64Mi 限制。引擎按支持的 LimitRanger 拒绝格式归因，并保留原始消息。

## 5. 拟实现的核心功能

已实现 UID 归属、列表完整性、分层诊断、结构化证据，以及 `--deployment`、`--json` 和 `--snapshot <file>`。配额根因需要明确的超限记录。数值佐证要求同名配额和同一资源项，并用 `requested > hard - used` 核对。只有饱和迹象时输出相关风险。其他创建失败保留原始证据，供人工判断。

本轮验证为 **53 个单测通过，9 个离线场景通过**。场景包括 4 份由 kubectl 从 RKE2 注入采集的快照、1 份派生的缺证据快照、4 份误报回归快照。CI 校验诊断层、证据字段和差额。LimitRange 插件参数复算、CPU/内存的副本差额估算及跨版本覆盖为后续范围。详见[评审答复与技术说明](PROPOSAL.md)。

## 6. 项目性质

原创 MoonBit 项目，Apache-2.0 许可。

## 7. 参考项目说明

kubemoon 用于集群访问，moonbitlang/async 用于异步 HTTP，Agent 线格式参考 mizchi/llm。外部基线涵盖 kubectl 人工取证、K8sGPT 分析器和 HolmesGPT 调查工具及公开评测。已验证的贡献为 MoonBit 内核对 Deployment 创建失败的字段级证据组合、配额差额和离线回归。外部工具依据官方资料对照，同场景实测仍待完成。见[基线表](PROPOSAL.md#外部基线)。
