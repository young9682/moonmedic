# moonmedic 项目申报书

## 1. 项目名称

moonmedic · Kubernetes 滚动发布路径分析与只读取证工具

## 2. 项目简介

Deployment 滚动发布卡住时，moonmedic 用只读快照判断在给定约束下，是否存在完成替换的动作顺序。诊断给出可行路径或受阻的依据，并附可离线核对的对象字段。

## 3. 项目方向与通用性说明

**04 开发者工具**。归属判断和路径搜索由 MoonBit 实现，可独立于 kubemoon 和 LLM 运行。其他工具可复用快照接口和 JSON 诊断。

## 4. 预期使用场景

1. **配额已满，该调哪个发布参数？** 用 `--snapshot` 从同一初态分别回放两种改动。目标 3 个副本，旧版 3 个可用，新版尚无 Pod，另有 1 个 Pod 占位，配额 4/4。快照里没有拒绝消息。只把 `maxSurge` 从 1 调到 2，新版期望数可升到 2，实际仍为 0。配额已满，旧版又必须保留 3 个可用副本。只把 `maxUnavailable` 从 0 调到 1，最低可用数降到 2，就能先退 1 个旧副本，等名额释放后创建新 Pod，待它可用再继续替换。[第三轮技术说明](https://github.com/young9682/moonmedic/blob/a81124b745c86f2b470fc73678593d58c3fa4885/docs/PROPOSAL.md#%E7%AC%AC%E4%B8%89%E8%BD%AE%E5%A4%8D%E6%A0%B8%E4%B8%AD%E7%9A%84%E6%BB%9A%E5%8A%A8%E5%8F%91%E5%B8%83%E5%8F%AF%E8%BE%BE%E6%80%A7)
2. **副本缺失**。期望 2 个副本，用 `--deployment` 核对归属 Pod、RS 的 `FailedCreate` 以及同名同资源的配额。E01 中零 Pod、配额 0/0，缺 2 个名额。E02 已有 1 个 Pending Pod、配额 1/1，只缺 1 个。
3. **两条拒绝都含 `is forbidden`**。查看归属 RS 的拒绝原文。[E03](https://github.com/young9682/moonmedic/blob/db589648b145acbe69b87dea9ab3baeff02ebbd4/eval/fixtures/e03-limitrange-reject.snapshot.json) 中 `maximum memory usage per Container is 64Mi, but limit is 256Mi` 命中 `limitrange_reject`。[R02](https://github.com/young9682/moonmedic/blob/db589648b145acbe69b87dea9ab3baeff02ebbd4/eval/fixtures/r02-generic-validation.snapshot.json) 中 `spec.template: Invalid value: unsupported field value` 只报创建失败和零 Pod。

## 5. 拟实现的核心功能

按 Deployment 模板识别新旧 ReplicaSet（RS），用归属 Pod 和配额用量核对初态。MoonBit 分开记录新版期望数、实际数、可用数和待释放名额，逐步检查哪些动作符合配额与最低可用数限制。广度优先搜索找到完整替换路径就还原动作顺序，穷尽可达状态才报告受阻。

模型限两个归属 RS、健康旧副本、整数发布参数和单一无作用域 Pod 数量配额，假设其他占用稳定、新 Pod 能就绪、缩容后名额会释放。证据不足或搜索达到 10,000 个状态时给出「未判定」。LimitRange 归因限于支持的拒绝句式和数值，第三方插件返回同样文案时仍需核对来源。

55 项单测、15 项离线回放通过。Kubernetes v1.33.1 的两次实测都从配额 4/4、旧版 3 个可用起步。只把 `maxUnavailable` 调到 1，先看到旧版缩容，540 秒时旧版为 0、新版可用 2/3。另一次保持策略不变，只把配额上限提到 5，最终旧版为 0、新版可用 3/3。[完整恢复](https://github.com/young9682/moonmedic/actions/runs/44674774969) · [部分恢复](https://github.com/young9682/moonmedic/actions/runs/44673527277)
